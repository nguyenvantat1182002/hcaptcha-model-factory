# External Integrations

**Analysis Date:** 2026-08-13

## APIs & External Services

**GitHub REST API:**
- GitHub Release & Deployment Management - Automated publishing of trained `.onnx` models to release assets
  - SDK/Client: `PyGithub` (`github.Github`, `github.Auth.Token`) in `automation/_04_mini_workflow.py`
  - Auth: `GITHUB_TOKEN` environment variable
  - Endpoints used: `get_repo("QIN2DIM/hcaptcha-challenger")`, release asset upload (`upload_asset`)

**Roboflow / Google Colab:**
- Remote model training notebook integration
  - Integration method: Jupyter Notebook reference (`automation/roboflow_resnet.ipynb`)
  - Target URL: `https://colab.research.google.com/github/captcha-challenger/hcaptcha-model-factory`

**External Image Sources / Downloaders:**
- Image dataset downloading scripts for labeling
  - Implementation: `automation/istock.py` and `automation/_01_datasets_downloader.py`
  - Integration method: Web crawling / scraping image assets into raw dataset folders

## Data Storage

**File-Based Image Database:**
- Local directory hierarchy for training, validation, and unlabeled image sets
  - Structure: `database/[task_name]/` or `data/[task_name]/`
  - Subdirectories: `yes/` (positive samples), `bad/` (negative samples), `unlabel/` (raw samples for auto-labeling)
  - Metadata formats: YAML manifests (`all.yaml`, `train.yaml`, `val.yaml`, `test.yaml`) generated by `DataModel` in `src/factories/kernel.py`

**Model Output Storage:**
- Model serialization directory
  - Location: `model/[task_name]/`
  - Artifacts: PyTorch checkpoints (`.pth`) and ONNX exported binaries (`.onnx`)
  - Archiving: Automatic timestamped subfolders (e.g. `model/[task_name]/[timestamp]/`) created by `ModelFactory._archive_previous_models()` in `src/factories/kernel.py`

## Authentication & Identity

**GitHub Token Authentication:**
- `GITHUB_TOKEN` env var checked in `automation/_04_mini_workflow.py` for automated asset upload and release deployment to downstream repositories

## Monitoring & Observability

**Loguru Logging:**
- Structured console logging using `loguru.logger` (`src/apis/scaffold.py`, `src/factories/resnet.py`)
- Standardized task diagnostics and input validation logs via `diagnose_task` in `src/apis/scaffold.py`
